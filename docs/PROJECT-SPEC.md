# ClipPlus — Project specification

## Purpose

Provide a lightweight substitute for the Windows clipboard-history popup, preserving native Copy/Paste and the familiar keyboard-first workflow. ClipPlus is a standalone Windows desktop application, not a Windows Shell patch.

## Accepted behavior

- Open with Win+V, subject to validating a stable supported interception mechanism. Do not modify system binaries or inject into Windows Shell. Consuming Win+V must not cause Start to open on modifier release; preserve standalone Win and unrelated shortcuts. If interception is unavailable, diagnose the conflict and offer a configurable alternate shortcut rather than silently breaking native behavior.
- Focus the search field on opening. Search user titles and text content immediately. For a nonblank query, real title matches rank before content-only matches, preserving pinned-first/recency within each tier. The No Title placeholder is not searchable as a title. Keyboard arrows and mouse selection navigate the filtered list; Enter pastes the original selected payload into the previously active application; Esc dismisses the popup. Direct mouse selection/paste must remain simple.
- Keep all pins across restart and up to 100 global unpinned recent items; evict only the oldest unpinned entries. Deduplicate equivalent copies without losing titles, colors, pin status or category. Pinned (visible when at least one pin exists) is the full global history, pins first followed by all unpinned recent clips. Recent (always present) displays only global unpinned clips. Both are fixed global views, not stored categories. A custom category displays its pins first and then its unpinned clips. Category assignment does not change retention. Clear clears all unpinned items, including categorized clips, and never clears pins.
- Display No Title for untitled entries. Clicking the title edits it in place; Enter saves, Esc cancels, and an empty title clears it. Titles never modify the actual payload.
- Allow each clip to have an optional persistent color. Place a compact color swatch next to the pin action; hovering for 350 ms or explicitly clicking/keyboard-activating opens a small palette of eight predefined colors plus Default (no custom color). Passing over a swatch without dwelling must not open it; explicit activation is immediate, and leaving or recycling the row cancels a pending hover. Wrap the choices as needed without horizontal scrolling. Use eight visually distinct hues and a stronger 12-DIP theme-aware colored edge, preserve readable text and provide named tooltips, a selected indicator and keyboard-accessible selection. Choosing or clearing a color must not paste, reorder, pin or modify the payload. Store the color with the clip metadata in SQLite and preserve it on restart, deduplication and pin/unpin. No custom color editor. Use borderless color swatches and retain selection, keyboard focus and high-contrast feedback.
- Offer up to ten flat custom categories via a fixed add button and a horizontally scrollable strip; wheel scrolling, drag reorder with edge scrolling, and Ctrl+Left/Right reorder are supported. Use borderless navigation category chips with subtle theme-aware inactive fills and distinct hover and active fills, small gaps, and visible keyboard focus. Add/assign uses the same native glyph sizing as card actions; named category controls and inline choices use consistent styling, spacing and text direction. Highlight the selected view. Double-click or F2 edits a custom category inline; Enter saves, Esc or leaving the editor cancels. Delete requires the X-to-check confirmation and detaches clips without deleting them. Names are nonempty, distinct (case-insensitive), and not reserved view labels. One optional category per clip, assigned/changed/cleared via a small card control. New copies are uncategorized. Persist custom order and selected view; invalid selection falls back to Recent, first opening prefers Pinned if available. Search is global with explicit scope, then restores the chosen view when cleared.
- In-card category choices use a borderless mouse/programmatic focus appearance, subtle selection and hover fills, balanced padding and wrapped row spacing, and keyboard-only focus feedback in both themes. Vertically center the empty-category hint beside No category, including narrow-width wrapping. Preserve all existing category semantics.
- Compact mode, toggled in the center of the footer and persisted, collapses previews only for titled clips. Keep title editing, color, pin, delete, category and explicit mouse paste in the compact header; Enter from search/list pastes normally. Untitled clips retain previews. Use a single shared search field with a 4-DIP corner radius, native text editing, existing height and insets, and theme-aware focus feedback. Align search, category strip and card edges with a single stable scrollbar gutter, balanced compact outer insets and a trailing-aligned indicator. Preserve the full native track hit area and resize border; keep card width stable with or without overflow, in ordinary and quick modes.
- The header pin toggle immediately before Close switches between ordinary popup and an always-on-top pinned quick-paste panel. Show only actual global pins in existing order, with title (No Title for untitled) and color accent, no preview or per-item management. Keep a pinned-only title/content search with title-first ranking, distinct empty and no-match states, and virtualized rows. Unrelated clipboard capture does not refresh the pinned-only list. Successful paste keeps the panel visible, clears the query, restores all pins and leaves focus in the external target. Failed, canceled or copy-only paste retains the query. Non-search pointer interactions within the expanded panel must not activate it; explicit search activation (including a click on the collapsed floating icon) remembers the validated external target. Resolve each new paste against the current foreground or the intended search target and cancel if it changes during the gesture or clipboard retry. Reuse the ordinary restore and native input path. Floating mode defaults to a draggable, non-activating 42-DIP icon with an independent saved position; outside mouse clicks collapse the expanded panel without intercepting the target gesture. Enable passive, event-driven outside-click detection only while the floating panel is expanded. Use mouse-only Windows Raw Input on a message-only window owned by the existing observer thread, consuming native queued screen coordinates (MSG.pt) and matching button-down/up transitions. Classify the press against its time-associated native rectangle, not geometry sampled after asynchronous queue delay. Keep only session-local rectangle transitions needed by pending input, retire obsolete transitions as input is consumed or the raw queue drains, and conservatively treat an exact shared native tick as inside if any applicable rectangle contains the press. No post-resize cooldown or fixed gesture-age limit. Ignore motion and wheel data; do not retain pointer history, poll, suppress input, collect payloads or add dependencies. The low-level mouse hook and move/size hook renewal are replaced, not retained as fallback layers. Idle alone never dismisses the panel; the first completed outside click after inactivity works without resizing, activation or rearming. If detection cannot start or terminates unexpectedly, keep the expanded panel usable and report the failure. Stop the observer using its owned event, unregister raw mouse input and destroy its message window before a new observer starts; keep the current surface and live observer intact if signaling fails, allowing retry. Native move/size tracking is for geometry persistence, not a permanent collapse veto: validate actual Windows modal-loop state on outside gestures and reconcile canceled or incomplete tracking through the existing placement path. The icon uses the canonical clipboard glyph on a single borderless circular blue glass-like surface, without an additional app-tile frame. Restore full opacity on hover/drag and fade to partial opacity after a short idle delay; honor reduced animation and opaque system high contrast, including live contrast changes while the icon is visible. Track the native dynamic contrast resource only while visible and cancel pending or active fades on entering contrast. The translucent surface uses native WPF alpha composition, not desktop capture or an unsupported backdrop API. The ordinary/quick panel uses a single anti-aliased rounded visible perimeter, with transparent exterior corners and the existing native resize hit testing. Click the icon or shortcut to reopen the full panel near the icon, clamped inside its monitor work area. An explicit icon click focuses Search while retaining the query and the validated external paste target; the shortcut and settings-driven reopening remain passive. If Windows refuses activation, keep the panel usable without inventing a target. After successful paste, return to the existing passive behavior. Temporary clamping does not change the saved icon position or preferred expanded size. Tray > Pinned panel behavior selects Floating icon (Auto-collapse) or Always expanded, persisted. Drag does not invoke Paste or open the panel. Search survives collapse and unsuccessful paste; successful paste resets it. Reuse unchanged pin entries during expand/collapse and unfiltered paste; refresh on real query/history changes. Release the icon window and outside-click observer when the quick session ends. Do not claim atomic foreground/input delivery or cross-integrity guarantees. Close hides both surfaces, Win+V reopens collapsed quick mode and does not dismiss an expanded panel, and the same toggle restores ordinary behavior. Quick mode has independent persisted position, width and height, native drag/resize, work-area clamping, and no automatic opening at startup.
- Allow header drag and native horizontal/vertical resize in both modes, preserving independent preferred position, width and height across switching, hide/reopen and restart. Initial ordinary/quick widths remain 360/260 DIP, with useful minimums of 260/160 DIP respectively, reduced only when the available monitor work area is smaller. Expansion is limited by the work area, not an arbitrary fixed maximum. Truncate long titles with ellipsis and retain their full tooltips and accessible names. Keep essential actions usable at narrow widths, including compact view. Clamp to the available monitor work area, including changed monitor/DPI configurations. Before the first manual move, place near the input context where supported; offer Reset popup position in the tray.
- Support text, HTML and images with original relevant clipboard formats preserved. Do not expand into a general file/snippet manager. Respect Windows clipboard history exclusion markers. Never include clipboard payloads in diagnostic logs.
- Support pin/unpin, delete, Clear with pins preserved, and system light/dark appearance. Keep the history scrollbar slim and rounded at rest, expanding on hover or drag with a usable interaction area, while preserving native WPF scrolling, keyboard navigation, mouse wheel and high-contrast behavior. A stationary mouse pointer must not override keyboard selection during scrolling.
- A single background process and a recognizable clipboard-plus icon for EXE, popup and tray, derived from the existing SVG design using a native WPF vector drawing for the header and native multi-size ICO frames for Windows; no polling loop for clipboard changes, no service, no cloud sync, accounts, telemetry, or network dependency.

## Technical direction

- C#, WPF, .NET Framework 4.7.2 or later; use the Windows-provided runtime and SQLite engine, without requiring modern .NET Desktop Runtime. Ship a direct portable executable and a conventional graphical installer. Build tooling may use modern .NET SDK, but the product must not require it. Preserve compatible SQLite schema and settings; use additive, transactional data migrations when needed, without losing history or metadata. Direct in-place upgrade acceptance covers the three most recent published stable releases preceding the candidate (Owner decision, 2026-11-27); select this rolling window automatically and verify exact released installer/executable hashes, update, failed-upgrade rollback and uninstall with both retained profiles. For older versions, recommend backing up retained data, uninstalling the old application and then installing the new version. Do not promise compatibility of arbitrary historical data or manual downgrades; do not impose a runtime version allowlist or remove actual data migrations solely because a release ages out of CI. Target Windows 10/11, validate representative environments where available, and do not impose an arbitrary build allowlist.
- Reuse Windows clipboard APIs and AddClipboardFormatListener / WM_CLIPBOARDUPDATE. Preserve the existing system clipboard semantics. Use Win32 foreground/window and input APIs to restore focus and paste; avoid recapture loops, handle clipboard contention, and report failed operations accurately.
- Local SQLite storage for history and metadata; JSON for window and app preferences. Keep per-user state separate from the installed executable. Elevated mode uses a protected per-user directory under Program Files/ClipPlusData; normal mode uses LocalAppData/ClipPlus. These histories remain separate so a privileged process does not consume medium-integrity-writable state. Use straightforward code, transactions and parameterized queries; no extra framework or search engine.
- The graphical installer offers elevated or normal startup privileges. Fresh installation defaults to elevated automatic startup in the interactive user session via Task Scheduler. Update preserves actual task RunLevel and enabled logon-trigger state unless the user explicitly chooses another privilege. The tray provides native checked Start with Windows and explicit confirmed startup privilege selection; disabling startup changes only the logon trigger and keeps manual demand-start and the running process available. Portable mode does not create tasks. The tray reports profile mismatch without moving data; setup warns if a running profile differs from configured startup. The per-user Programs shortcut has the visible name ClipPlus; migrate only the verified owned common SID link. Use a temporary Limited interactive task to operate on the user-writable Programs location, preserve unrelated links and restore the old link on rollback. Persist the exact shortcut staging identity in the protected setup journal, publish trusted shortcut bytes by a no-overwrite same-volume rename, and recover both complete and partial staging copies without deleting unrelated files. Install the executable and any loadable code in a protected Program Files path. Never use SYSTEM, disable UAC or store executable/configuration that controls privileged execution in writable locations. Installation/uninstallation must register/remove only ClipPlus-owned, account-scoped application, scheduled task, shortcut and registration resources. Validate prerequisites and payload integrity before replacement. Preserve the prior package and configuration through the wizard commit boundary, roll back failed or canceled installation/update, and resume interrupted setup or rollback on the next trusted wizard invocation. Preserve history and settings on update and ordinary uninstall. Provide a non-elevated launch option and actionable errors if elevated startup cannot be configured. Do not attempt to interact with the secure desktop.
- The temporary shortcut helper must complete the current invocation before its result is accepted. Running, queued, stale and not-yet-run observations are nonterminal; retain bounded timeout and diagnostic state, actual helper failures, transaction recovery and ownership checks.
- No Foundation dependency: this is a product-local Windows desktop capability. Reuse native platform capabilities instead of introducing shared abstractions.

## Completion and validation

Exercise Win+V, focus restoration and paste in ordinary and elevated Windows applications where suitable environments are available. A Windows build and Linux cross-build alone do not prove interactive runtime behavior.

Realize cards using native WPF virtualized pixel scrolling; preserve selection by clip ID, defer updates during active editing or pressed actions, avoid rebuilding unchanged collections and load image previews lazily. Compare representative Windows WPF before/after elapsed layout and dispatcher timings and realized-card counts; do not claim client responsiveness solely from a build.

Validate keyboard/mouse navigation, title edit, search, color selection/reset and persistence, keyboard-accessible palette without accidental paste, theme contrast, pinned ordering, retention/duplicates, restart persistence, drag, persisted position, resizing and screen bounds, supported clipboard formats, clipboard exclusion markers, contention and self-paste handling, and installation/startup/update/uninstall. Update must preserve history/settings. Use interactive Windows evidence for hotkeys (including Start-menu regression), foreground focus, paste, DPI and elevation where available; use targeted automated tests for deterministic state and storage behavior.

Initial v0.1.0 acceptance boundary (Owner decision, 2026-11-24): successful exact-candidate Windows CI, including interactive desktop and installer lifecycle tests on the available Windows runner, plus the Owner's representative hands-on testing of earlier candidates, are sufficient for the initial release. A full Windows 10/11 client, older Framework, filtered ordinary-token, two-account, mixed-DPI, physical shell shortcut and logoff/logon matrix is not a release prerequisite. Those cases remain unverified unless actual evidence is recorded; disclose material gaps in release notes. This is acceptance of validation scope, not acceptance of known implementation defects or a waiver of independent review. Subsequent releases use validation proportional to their changes.

Distribution: first-party source code under MPL-2.0, source availability and license notice in the binaries and release artifacts; third-party licenses retained. Publisher metadata: AChWorks. Publicly trusted Authenticode signing is optional until a suitable verified signing identity is available; do not claim verified publisher identity for unsigned binaries.

Delivery: reproducible Windows build process, tested installable package and documentation, exact-candidate independent review and owner-authorized merge/release. Publish verified production binaries, matching checksums, corresponding source, license and notices. Use [GitHub Releases](https://github.com/AChWorks/clipplus/releases) and linked CI evidence as the authoritative record of published versions and validation.
